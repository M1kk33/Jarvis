# Implementation audit corrections — 2026-10-08

The fixes preserve the existing architecture, models, tool set, explicit retrieval policy, and private user data. Migration 008 adds an acknowledgment timestamp to tool invocations; it does not reset, delete, or rewrite conversation content.

| Finding | Correction | Regression coverage |
| --- | --- | --- |
| I1: approvals bypassed job ownership | Approval execution and continuation run under the runner's execution lock and active cancellation registry. SQLite rejects concurrent execution. Server shutdown cancels dispatched jobs and waits for cleanup. | Approval behind inference, two approved jobs, repeated cancellation, retained receipt, shutdown |
| I2: cancelled tool success lost its receipt | Both ordinary and cancellation recovery paths validate and commit worker results before propagating cancellation. Commit and cleanup settlement tolerate repeated cancellation. | Successful and failed worker results after repeated cancellation |
| I3: cancelled submission accepted changed input | Recovery compares stored text and input kind. Legacy submission cancellation retains the actual submission result, so it cannot interrupt a pre-existing duplicate turn. | Identical ID/text, changed text, screenshot/text collision, legacy duplicate ownership |
| I4: uncertain speech cleanup released shared admission | A domain cleanup error poisons the shared speech gate and ResourceManager before releasing the CPU lease. This also applies when no heavy runtime is configured. | Transcription and synthesis failures, cross-capability admission, shared legacy locks, heavy admission |
| I5: wrong GPU became missing telemetry | Successful UUID/index disagreement or an absent index fails closed. Profiles accept full canonical UUIDs, case variants share one lock, and workers see only that physical UUID as CUDA device zero. | UUID mismatch, case variants, reordered/missing indices, rejected aliases, captured text/image launch settings |
| I6: Windows transcript encoding and tail limits disagreed | Worker output writes explicit UTF-8 bytes and checks the complete JSON line against the 64 KiB protocol bound. CPU worker environments also specify UTF-8. | Real supervised Windows child with multilingual output and an oversized encoded transcript |
| I7: trickle responses escaped the deadline | A deadline monitor interrupts the live socket during headers/body/TLS. DNS waits poll cancellation; application cancellation signals the downloader and waits for connection cleanup. HTTP responses are explicitly closed. | Real socket trickle during headers/body, absolute timeout, cancellation, fetch/render application propagation |
| I8: uncertain actions were hidden and permanently blocked new work | Authenticated history exposes proposals and receipts. Trusted acknowledgment after job cancellation allows independent new turns while retaining `outcome_unknown`, the timestamp, and replay restrictions. Exact file reconciliation remains available. | Crash recovery, protected endpoint, terminal-job requirement, idempotent acknowledgment, restart persistence, no fabricated receipt or replay |
| N1: private files lacked ignore rules | Ignore local profiles, environment files, model/runtime files, logs, artifacts, and backups while preserving examples and fixtures. | Git's actual ignore behavior |
| N2: provider and registry argument limits disagreed | Both use the same bounded per-tool argument limit, including streamed assembly and final validation. | A legal file proposal over 4 KiB and rejection of an oversized ordinary tool call |
| N3: stored and enforced deadlines differed | Execution segments use the persisted ten-minute deadline, including approved-action continuation. Waiting for approval pauses execution; approval starts a fresh segment within the same attempt. | Expired stored deadline fails before provider execution |

Validation uses temporary databases, deterministic providers, model-free Windows workers, local sockets, recorded streams, and authenticated local API requests. Real GPU/model/speech quality qualification and memory calibration are not rerun by these offline checks. Existing calibration numbers are not new measurements of these changes.

Verification: 291 offline Python tests, including 42 new audit regression cases, and six JavaScript tests pass. Ruff checks/formatting, mypy (58 source files), dependency lock/compatibility checks, JavaScript syntax, and Git whitespace checks also pass. Warnings are treated as errors in the Python suite. GPU case normalization retains the established normal UUID lock/journal key and accepts equivalent saved job identities without changing their stored values.

Recovery instructions are in the README. Acknowledgment is a user decision about accepting uncertainty; it is never evidence that an action succeeded or failed.
